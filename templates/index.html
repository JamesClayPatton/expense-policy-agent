How this was built, and what the evals found

An interview take-home: build an agent you would trust, then prove it with evals. The agent retrieves the policy sections that apply, runs three database checks, decides, and a guard in plain code downgrades any approve that breaks a hard rule. A second model judges the explanation. 56 test cases across eight slices, scored by seven deterministic checks and the judge, in LangSmith.

  1. Baseline: 73% correct. Every missed citation was a retrieval miss. An expense never sounds like the rules on approval authority or duplicates, so those sections were never in context.
  2. Fix retrieval: citations to 98%, accuracy down to 66%. With the approval section always visible, the model flagged every claim with no approver on record. The policy says every reimbursement needs an approver other than the claimant, and nothing had told the agent that it is the approver. The fix exposed an ambiguity the baseline had hidden by never reading the section.
  3. Prompt revisions and a date guard: 86% correct, error cost from 0.13 to 0.04. One paragraph says who the agent is. A guard rule handles the 30-day deadline, because the model miscounted day 31 in every run.
